# Spintax

Produces spintax versions of campaign email copy so the same sequence sends as
many surface variants. Content only: never sends, never edits a campaign in
Instantly, never overwrites a file without showing Ravi the before/after.

## Where it fits

Emails are generated by `outreach-content-agent` and sent via Instantly.
Decisions approved by Ravi 2026-11-15:

- **Spintax is resolved in the pipeline, per lead, seeded** (seed from
  `sha256(campaign_id + ":" + lead_id)`). The agent renders one fixed variant per
  lead and QA-gates that rendered text. Spintax is not left for Instantly to
  resolve at send time. It never changes what a claim says.
- **Where spun copy lives:** in `outreach-content-agent`, per campaign under
  `data/clients/{client}/campaigns/{id}/spin/`: `email_{n}_{name}.spin.md` (one
  per step), `library.json` (banned phrases, spun subject bank, spun
  proof / magnet / offer items with `fixed_terms`, slot declarations) and
  `slot_guide.md`. The binding format contract is
  `outreach-content-agent/docs/phase6-formats.md`; follow it over this skill
  where they differ.
- **Spin the scaffolding:** subject lines, greetings, transitions, sign-off
  lead-ins, bump and break-up emails (steps 2+).
- **Offer, proof and lead-magnet lines ARE spun, framing only.** Vary the
  lead-in, verb framing and clause order. Facts, names, titles, numbers and
  quoted words stay exact in every option (list them as `fixed_terms`). Example:
  `{For reference|For context}, Everywhen's Technology Director {says|has said}
  ... "within a matter of days" of customer feedback.`
- **Do not spin per-lead evidence:** slot values from the lead's row (hiring
  signal, company fact, names, quoted material) are `{{slot}}` placeholders,
  never spun. Pricing and links are never spun.
- **Banned in every option:** "told us", "we helped", "we work with" (a client
  may have no customers in the target market and never spoke to the proof
  source; GolemUI is the case that set this), plus the campaign's
  `sequence_spec.md` banned list. Store them in `library.json`
  `banned_phrases`.

If copy is nearly all per-lead evidence, say so and spin only the scaffolding.
Do not force variation into it.

## Syntax (Instantly)

- Variation block: `{Hi|Hello|Hey}` — single braces, options split by `|`.
- Merge variables: `{{first_name}}`, `{{company_name}}` — double braces, left
  exactly as they are. Never put a variable inside a spin option that changes
  its meaning; `{Hi {{first_name}}|Hello {{first_name}}}` is fine, a variable
  alone as an option is not.
- Nesting is allowed but keep to **one level**. Deeper nesting is unreadable
  and breaks in some tools.
- Empty option for optional words: `{Quick note|}` is valid but use sparingly.
- A literal `{`, `}` or `|` in prose must be avoided or reworded.
- Tool-agnostic fallback only if Ravi names another sender (Smartlead, lemlist
  use the same `{a|b}`; Mailshake differs). Ask which before assuming.

## Rules for good variants

1. **Meaning-equivalent.** Every option in a block must say the same thing at
   the same register. No option may add, drop or soften a claim, number, or
   commitment.
2. **Grammar-safe in every combination.** Spin at phrase boundaries so any
   pick from any block still reads correctly (check agreement, articles,
   punctuation, capitalization after a period).
3. **2–4 options per block, 4–8 blocks per email.** More makes copy generic;
   fewer does not vary enough. Short emails get fewer blocks.
4. **Vary structure, not just synonyms.** Swapping synonyms alone ("help" →
   "assist") is the thing filters key on. Also vary clause order and sentence
   openings where it stays natural.
5. **Keep the voice.** Match the client's `company_brief.md` voice section and
   the language of the email (the agent writes in the lead's detected language
   — spin in that language, do not translate).
6. **No filler openers** ("I hope this finds you well") — same hard rule as
   the generator. Spinning must not reintroduce them.
7. **Subject lines:** 3–5 variants, all lowercase-or-sentence-case consistent
   with the campaign, no spammy punctuation, no emoji unless the campaign
   already uses them.
8. **Never alter** URLs, numbers, named proof companies, titles, quoted words,
   the lead magnet name, or the CTA's actual action (e.g. "reply with yes"
   stays "reply with yes"). Fixed asks such as "Worth 15 minutes?" are never
   spun.
9. **Optional placeholders** `{{name+}}` (value plus a space, or nothing) and
   library includes `{{lib:key}}` are pipeline syntax from
   `docs/phase6-formats.md`. The validator's variable regex does not accept
   `+` or `:`, so rename them (e.g. `{{name_OPT}}`, `{{LIB_key}}`) or inline the
   library text in a temp extract before validating.

## Workflow

1. Read the input: a campaign's email copy (e.g. `emails/*.md` or
   `sequence_spec.md` under `data/clients/{client}/campaigns/{id}/`, or text
   Ravi pastes). Note which parts are static vs per-lead evidence.
2. Draft the spun version, one email at a time.
3. Run the validator on each spun email (below). Fix and re-run until clean.
4. Show Ravi the original and spun versions side by side, plus the validator's
   combination count. Write to file only on an explicit yes, to a new file
   next to the source (`{name}.spin.md`), never over the original.

## Validator

```
python .claude/skills/spintax/scripts/spintax_check.py FILE_OR_- [--original ORIGINAL] [--sample N]
```

Reads a spun email (`-` for stdin) and checks: balanced single braces, no
empty or single-option blocks, no duplicate options in a block, no nesting
beyond one level, `{{vars}}` intact, total combination count, and — with
`--original` — that every `{{variable}}` and every URL/number from the
original still appears in every option path. `--sample N` prints N random
rendered variants to read for grammar. Exit code 1 on any failure.

Always read at least 3 sampled renders yourself. The validator catches
structure, not whether a combination sounds right.

## Output format

For each email, give:

```
STEP n — subject
  Original: ...
  Spun:     ...
Validator: OK · <combinations> combinations · <blocks> blocks
Sample renders: 3
```

Then list anything deliberately left unspun and why (per-lead evidence,
fixed offer text).
